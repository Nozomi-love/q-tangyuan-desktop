# Q弹汤圆 2.0 开发指南

[项目首页](../README.md) · [玩家指南](使用指南.md) · [目录说明](目录说明.md)

## 环境

Windows x64 为当前构建与实测平台。源码要求 Python 3.10+，推荐 Python 3.12；历史实测解释器为 3.12.6。运行依赖为 `requirements.txt` 中的 PySide6 6.8.3，构建依赖另见 `requirements-build.txt`。

Python 3.10 仅检查语法兼容，未在该解释器下完成全部运行验证。

## 从源码启动

```powershell
git clone https://github.com/Nozomi-love/q-tangyuan-desktop.git
Set-Location -LiteralPath '.\q-tangyuan-desktop'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

使用虚拟环境解释器完整路径，无需激活脚本或修改 PowerShell 执行策略。终端没有 `python` 时先安装 Python 并确认命令可用。验证更新前，从旧进程的托盘退出，否则二次启动会唤醒旧程序。

## 启动模式

| 参数 | 用途与数据影响 |
| --- | --- |
| 无参数 | 正式玩家模式，隐藏调试入口，使用正式存档 |
| `--version` | 输出产品版本并退出 |
| `--demo` | 每次新建独立演示存档，不修改正式进度 |
| `--dev-mode` | 调试入口、加速计时与无限糯米币；单独使用仍操作正式存档 |
| `--demo --dev-mode` | 推荐验收方式：独立存档与开发入口 |
| `--resume-demo 路径` | 继续 `tests/artifacts/` 下已有演示 save_data.json，不能与 --demo 同用 |
| `--smoke-test` | 真实窗口约 2 秒后输出诊断退出，不写玩家进度 |
| `--smoke-report 新路径` | 配合 --smoke-test 保存新的 JSON 报告 |

```powershell
.\.venv\Scripts\python.exe main.py --version
.\.venv\Scripts\python.exe main.py --demo --dev-mode
```

开发模式HUD显示“无限”，购买不扣存档实际余额；模式标记只在本次进程有效，正式启动仍按真实余额扣费。库存、永久购买所有权、经验等仍正常保存到当前档，推荐 `--demo --dev-mode` 隔离验收。无限币不替代TES专属、等级、重复购买和特技冷却规则。

开发计时为饱食每 2 秒减 1、收益每 10 秒、新风味 15 秒，房间日常可缩短至 2～4 秒。设置内可预览昼夜、日常、礼物与等级奖励。继续演示时，使用上次打印的实际路径，不把示例占位文字当文件名。

## 架构

十二个 Python 模块通过信号槽连接。`models.py` 是养成结算唯一入口，`pet_engine.py` 推进共享物理与统一渲染，`home_scene.py` 组合房间只读姿态而不重复结算。`main.py` 协调双窗口与托盘，`dashboard.py` 提供小窝和同屏抽屉。存档和皮肤沙箱在 `save_manager.py`，单实例与备份服务在 `release_support.py`。新增 `item_expansion.py` 集中首批道具矢量插画、临时道具与姿态函数。新增 `room_art.py` 集中透视架构、家具明暗、纸张肌理和只读房间PNG图层，`home_scene.py` 保留行为与图层顺序。新增 `content_registry.py` 集中已实现特技与挂件的冻结注册元数据、槽位和图标ID，供模型、界面、引擎和构建清单共同校验。完整职责见[目录说明](目录说明.md)。

## Part 1共用底座

[Part 1底座验收](Part1底座验收.md)记录本批范围与操作。head、face、back、effect各用独立图标槽选择；旧墨镜布尔值迁移为face ID，未知安全ID保留存档但不获新权限或绘制不明商品。新增内容必须先在代码注册并具备处理实现，再配置价格和等级；仅向JSON塞一个ID不能创建商品或特技。Part 1交付时只有原有五项特技；Part 2现已追加反向闪现，其余五款新设计按Part 3～6开发。

最近3条本机互动摘要保存在 `interaction_history`，只含受限事件类型和安全物品ID，由模型写入并随schema5存档恢复；界面与场景只消费快照，不记录截图、自由文本、剪贴板或网络资料。演出受理、自然结束和取消使用统一生命周期事件，取消只清理临时表现，不重复结算。房间捕获自己的实际脚底，不能推进第二份桌宠物理。

## Part 2练习与走位篇

[Part 2验收](Part2练习与走位验收.md)列出10款新品、组合和启动方式。新增代码沿用现有十二模块，catalog与注册表共同约束28消费品/23家具/15含旧装扮/6特技；116图标共享构建允许清单。

`practice_experiences`只接受练习册、沙漏与训练假人三个体验，schema5缺省为空。两个赠礼按模型成功消费记录；房间仅在成功激活已布置家具时向控制器发出 `furniture_interacted`，由模型校验并记录，预览不计。称号没有额外金币/EXP。

`RoomPetView`只读组合房间偏移；反向闪现独立限制房间实际位移，不继承桌面固定坐标。 通过 `prepare_trick()` 在引擎启动前捕获实际脚底；独立场景调用也使用 `prepare_trick → engine.perform_trick → begin_trick`。反闪camera围绕该脚底固定适配，普通镜头按左右余量缩放避免为巨型挂件挪HOME；真实点击的多路信号清理保持幂等。两新食品用到达后3秒清场时钟，旧食品时长保持；所有专属图标/粒子归属同一临时演出，结束和输入中断清理。

## 自动化测试

项目根目录执行：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -p 'test_*.py'
```

离屏可能提示托盘不可用；真实音频、窗口和 Windows 多进程行为用原生检查：

```powershell
$env:QT_QPA_PLATFORM = 'windows'
.\.venv\Scripts\python.exe -B -X utf8 tests\verify_quiet_position_native.py exercise
.\.venv\Scripts\python.exe -B -X utf8 tests\verify_inventory_native.py
```

原生脚本会暂时打开测试窗口并退出。位置脚本exercise阶段会打印独立档目录；用同一路径分别运行read-pinned和read-free阶段可检查跨进程恢复。旧原生脚本可能覆盖已移除的自定义导入入口，现行路径使用上述脚本。证据保留 `tests/artifacts/`，不使用正式档。测试名的 `phase` / `v2` 保留历史阶段含义。

## 构建 Windows 便携版

在 Windows x64 的项目环境中：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -B -X utf8 tools\build_windows.py
```

脚本每次在 `releases/` 新建构建与输出目录，最后打印 EXE、ZIP、数量与 SHA-256。目录版便携包须完整发送，不能只发送 EXE。

资源使用允许清单，收录默认与八款内置队标皮肤、图标、音效、配置与样式，排除个人存档、用户皮肤、测试、备份和凭据。包内有开始使用说明、散列清单与第三方许可。构建前确认默认资源确实可供公开分发。

对实际生成的新 ZIP 运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 tests\verify_distribution_native.py --zip 'releases\实际构建文件名.zip'
```

该检查解压到新目录、核对散列 / EXE 版本 / 图标，并在 PATH 无 Python 的环境下检查源码和 EXE 正式 / 开发冒烟启动。本机通过不能替代其他电脑实测。

本次GitHub发布为源码版，没有附新EXE；构建脚本更新了2.0版本信息与开始使用说明。

## 版本与数据

当前 **2.0.0**。版本标识在 `release_support.py`、Qt 启动版本和 `tools/windows_version.txt` 保持一致，分发验证同步预期。

产品版本与存档 schema 独立。本次不降低 schema，不改变 Qt 应用名称、任务栏、数据目录或单实例身份，避免因改名而使数据分叉。源码和 EXE 之间迁移使用软件备份恢复。

## 协作边界

提交前检查差异和相应测试。图标优先读取同名 PNG，默认原图与用户素材保留原件。不要提交玩家档、`user_*`、`.preview_*`、`tests/artifacts/`、`.venv/`、`releases/` 或本机快捷方式。

项目源码与素材当前没有统一开源许可证。第三方许可文本见 `tools/licenses/`，默认素材见[来源记录](素材记录.md)。
