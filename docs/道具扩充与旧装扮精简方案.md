# 道具扩充与旧装扮精简方案

**状态：首批16件与旧装扮精简已在本地实现，其余44件仍为设计稿。** 用户选择均衡扩充礼物、装扮和家具，并允许精简无意义旧装扮。本文规划60件新品、9件旧装扮取舍、10组关联演出与6个附加称号；本地实现与验收见[首批道具验收](首批道具扩充验收.md)，本轮未更新GitHub。

## 设计方向

- 物品先有动作与包袱，再决定数值；避免只换名字、换颜色。
- 软萌造型保留，内容以赛事语境、嘴硬、自嘲和前后回收为主。
- 礼物基础经验维持20/80/240，食物仍零好感；组合不额外发币或重复结算。
- 所有新品图标计划用80px透明插画：暖深棕圆描边、柔和填色和少量高光；首批16件图标已生成，其余44件仍只有造型规范。
- 价格是待平衡的设计价，沿用现有三级消耗品价位，不在这次设计中修改在线收入。

## 实施时必须沿用的行为约束

1. 先结算一次，再发带物品ID的表现事件；满饱/满级只显示实际增量，演出不能重复消耗。
2. 临时道具只活在本次演出里：自然结束/点击/喂食/拖拽/新特技/停场均清理；家具则只由已装备槽位决定。
3. 保存本次房间起点，接近/回程使用同一锚点；动作中断保留当前位置。纯演出不修改固定桌宠坐标。
4. 遥控器、屏幕、Flag只保存本机游戏事件。没有用户主动输入或比赛数据，不能假装读懂真实赛果。
5. 可交互点击不是领取收益的门槛：例如击拳没人点也正常结束，奖励不变，不做限时惩罚。
6. 新家具、挂机、时钟、装备待机均无自动响铃；音乐只在用户主动使用后短播，遵守总静音，素材用原创合成而非商业歌曲。
7. 粒子单演出上限16颗，最多一个前景演出；组合复用当前演出，不叠三倍特效或音量。
8. 旧装扮不物理删文件、不重置解锁/称号/成就；迁移、最大缩放、边界、视图隐藏、队列和重启需有回归覆盖。
