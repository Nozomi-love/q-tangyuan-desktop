# Part 1：商城特技与演出共用底座验收

[分Part计划](道具与特技分Part开发计划.md) · [开发指南](开发指南.md) · [目录说明](目录说明.md)

日期：2026-10-24（北京时间）。本批实现共用底座，**不增加商品数量**。原16件已实现道具保留，余下44件道具及6款新商城特技仍按Part 2～6开发，没有提前上架占位卡片。

## 本批可以看到的变化

- 背包的挂件页分为头部、面部、背部、周身四个独立图标槽，每槽可选一件或“不佩戴”。等级与商城所有权继续生效。当前面部仍只有墨镜；多商品底座不等于本批新增了面部商品。
- 特技列表和槽位权限由 `content_registry.py` 的已实现注册表统一提供，界面、模型和引擎使用同一套ID。原有空翻、影分身、弹力球、绕屏、迪斯科继续可用。
- 本机互动只保存最近3条简短结构化记录，随存档恢复，供战术大屏及后续Flag/复盘使用。记录由模型接受操作时写入，房间和抽屉不另计一次收益；旧档缺此字段按空记录读取。
- 特技、食品和礼物接入统一演出生命周期：自然完成、主动打断、替换、隐藏、换皮肤和退出均清理本次临时表现。房间先保存自己的实际脚底，再消除临时姿态，静置后沿既有生命周期回窝；不把桌宠物理位置写成房间位置。
- 开发模式继续无限糯米币，正式模式仍按存档真实余额扣费；无限币不解锁等级、TES资格、冷却或库存限制。

## 启动

先从旧进程托盘退出，避免单实例机制唤醒仍在运行的旧代码。在项目目录执行：

```powershell
Set-Location -LiteralPath 'D:\Codex\Q弹汤圆'
.\.venv\Scripts\python.exe main.py --demo --dev-mode
```

该命令使用独立演示档。控制台会打印实际存档路径，保留该路径以测试重启恢复。开发加速会较快消耗饱食度；若只想慢慢验收外观，可在设置里关闭“加速养成计时”，开发无限币仍保留。

普通玩家模式为：

```powershell
.\.venv\Scripts\python.exe main.py
```

普通模式使用正式档，默认隐藏调试入口；不要为测试归零等操作修改正式进度。

## 建议验收顺序

1. **无限币与权限**：右上角显示“无限”。在商城购买食品、礼物、家具、皮肤、装扮及绕屏特技，检查库存/永久拥有正常增加。重复购买永久物品应拒绝；等级奖励家具不能靠无限币购买；TES乐器仍检查当前皮肤。六款新设计此时不应出现。
2. **四槽换装**：设置中打开“全部等级特权试用”，进入“背包 → 换装 → 挂件”。分别选择皇冠、墨镜、凤凰翅膀/背包、红温热气/冠军聚光灯，再逐槽选“不佩戴”。房间实时变化，每个槽最多一个高亮，不连带清空其他槽；调高度后换皮肤仍按原规则分别记忆。
3. **旧档兼容**：通过软件备份恢复测试副本，原有收藏、背包、币和称号不重置。旧墨镜布尔开关迁移到面部槽。已下架嫩芽/蝴蝶结/萤火虫不回到新商品或奖励列表；旧档已穿戴的效果可保留，换下后不能重新选择。未知安全ID保留原数据，界面与有效渲染回退为空槽，不获得未实现商品的权限。
4. **本次起点与最终回窝**：等待汤圆走到地毯以外，再表演空翻或绕屏。演出末尾应回本次起点；继续观察结束后0.5秒、超过1.5秒和足够走回地毯的时刻，应平滑归窝。放大皮肤并使用黑芝麻Buff再检查一次，判断实际脚底，不能只看角色中心。
5. **连用与中断清场**：送陀螺、使用其他礼物、投喂、发动特技，再分别戳一戳、摸头、拖动桌宠、隐藏主窗或切换皮肤。旧道具、残影、粒子和姿态必须清场；重开房间不重播旧队列、不重新扣库存、不补领一次收益。反复打开/收起背包或商城抽屉本身不应取消正常房间显示。
6. **固定桌宠与自由桌宠**：两种状态分别跑一次上面的特技与打断流程。固定桌宠脚底保持固定，临时演出不成为新保存位置；自由桌宠依照已有工作区与重力规则运行。房间不因桌宠抛投高度悬空，也不重复推进桌宠物理。
7. **最近3条持久摘要**：购买并布置战术大屏，依次戳戳、摸头、投喂、送礼，检查大屏只展示最新3条操作图标。保存退出后，使用 `main.py --dev-mode --resume-demo "控制台打印的完整save_data.json路径"` 重开（此时不加 `--demo`），记录应恢复。购买本身、重绘、开发预览和拒绝的操作不得变成第二条成功互动。

互动摘要仅保存受限事件类型和安全物品ID，不保存截图、自由文本、剪贴板、直播弹幕或联网资料。正式存档与演示档按路径隔离。
