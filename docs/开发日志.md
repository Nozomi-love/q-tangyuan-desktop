# 开发日志

时间使用北京时间（Asia/Shanghai）。本文件记录需求、决策、已完成实现、实际验证和未完成事项；Git 提交记录对应引入 Git 之后的实际变更。

## 2026-10-16：架构确认

- 产品为本地离线的桌面陪伴宠物与免费养成游戏，默认白汤圆。
- 确定 Python 3.10+、PySide6、Qt Widgets、QPainter、后续 GIF 使用 QMovie。
- 采用共享数据模型、桌宠悬浮窗、养成主面板和系统托盘。
- 用代码形变实现呼吸、Q 弹回弹和抛投；皮肤内容与变换分离，后续饰品使用独立图层。
- 明确零惩罚：饥饿归零饿扁但不死亡、不扣好感；好感只增不减。
- 分四阶段实施，核心模块规划为 main、models、save_manager、pet_engine、pet_window、dashboard。
- 双击用于主面板，空翻将使用独立菜单入口，避免交互冲突。

## 2026-10-16：用户素材适配

输入：
- 四张 1254×1254 的元宝汤圆，依次为待机、开心、眩晕、难受。
- 素材实际为白底 RGB PNG，缺少透明通道；眩晕图另有悬浮星星。
- 用户保留原始图片命名，使用 expressions.json 建立状态映射，同时兼容标准文件名。

实现：
- 在加载时去除与边缘连通的近白色区域，保护主体内部的白色；不重写原始 PNG。
- 使用最大连通主体确定缩放和碗底锚点，单独保留全图的悬浮星星，避免眩晕状态突然缩小。
- 主体等比显示，保留元宝碗形状；呼吸、点击回弹、拖拽、抛投和饿扁继续作用于统一变换。
- 初次解码后生成最长边 768 的缓存；正常动画帧不重复解码或去背景。
- 托盘图标采用实际待机图片，图片热加载时同步更新。
- 输入映射限制在皮肤目录内部，防止错误路径指向目录外文件。

验证：
- 34 项行为测试通过，新增外白底/内白色保留、悬浮特效不改变主体、原始文件映射与目录边界测试。
- 四张实际素材全部加载，原始 SHA-256 在适配前后保持一致。
- 原生窗口/托盘与 150% DPI 锚点验证通过，截图已目视核查。
- 四种表情预览已保存到 docs/images/phase1-artwork.png。
- 标准文件名与缺图兜底测试继续通过；没有开始 Phase 2。
