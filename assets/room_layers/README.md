# 房间手绘图层

这个目录允许用透明 PNG 无损替换房间矢量画面。不放图片时，软件仍完整绘制立体房间。加载器只读现有素材，不生成或覆盖画师文件；坏图、超限图会回退到矢量。

## 命名与优先级

1. `<theme_id>.png`：替换该主题的整个背景，包括墙地、窗外和固定书柜。装备的家具、灯光、角色、互动、前景和界面仍独立绘制。示例：`cheese_room.png`。
2. `<theme_id>__<stage>.png`：分别替换某个主题的单一场景层。示例：`cheese_room__walls_floor.png`。
3. `<furniture_id>.png`：替换已装备的对应家具；例如 `cloud_cushion.png`、`warm_lamp.png`、`sunflower_painting.png`。默认固定窗框和矮书柜使用 `window_frame.png`、`low_bookcase.png`。

主题 ID 来自 `config/catalog.json` 的 theme 家具：`cheese_room`、`sakura_room`、`matcha_room`、`camp_room`、`postmatch_studio`。家具 ID 同样取自该配置。不使用名称中的中文或商城显示文字作文件名。

分层管线为：

`outdoors` → `walls_floor` → `back_furniture` → `lighting` → `middle_furniture` → **角色** → `foreground`

- `outdoors`：窗外天空、远山、树冠。仅放在窗洞区域，其他区域透明。
- `walls_floor`：墙壁、转角、踢脚线与透视木地板。窗洞应透明以显示上一层。
- `back_furniture`：固定窗框、窗帘、书柜。可购买的挂画/挂钟/空调仍由各自家具 ID 控制。
- `lighting`：环境染色、窗光、灯光。建议低透明度，避免覆盖角色细节。
- `middle_furniture`：地毯、小茶几。整体替换本层时需将两者画齐；只换单件请用家具 ID。
- `foreground`：前景案几、顶部串灯和垂叶。控件由 UI 另外放置，不把文字和按钮画死在图片中。

角色层始终走同一套 PNG/GIF、表情、挂件、风味和特技管线，不提供 `__pet.png` 替换。皮肤素材放原有皮肤目录。

## 尺寸和锚点

- 图层建议制作 1920×1200 或更高比例相近的 RGBA PNG，以 960 宽的逻辑画布为基准。图层按可用场景伸展适配；前景控件在窄房间会自动改为两行，建议透明留白。
- 单件家具使用透明背景、主体完整居中，会等比缩放到该家具槽位，不拉伸。
- 动态交互与点击热区沿用槽位锚点。替换画师图请尽量匹配槽位包围盒；不能在图中随意把主体移到另一端。
- 左墙转角为宽度的 22%，后墙地脚约高度的 61%；木板向同一消失点延伸。窗户在后墙右侧，挂画在后墙左上区域，落地灯避开挂画。
- `foreground_table_rect()` 与 `foreground_navigation_rect()` 返回实际控件使用的窗口像素位置，尺寸变化由 UI 与场景同步。

## 本地安全与分发

- 单文件最多 20 MB；源图片最多 3200 万像素，读取时最大纹理边长缩到 4096。
- 仅接受安全的 ASCII ID 与 PNG，拒绝路径穿越、符号链接和 Windows 目录联接。
- 不存在或不安全的图不会影响角色和存档。缓存按修改时间更新，重新绘制即可读取合法替换图。
- 打包脚本仅收集配置中的家具/主题 ID、上述显式图层名与固定窗框/书柜，不递归收集本目录其他素材。
- 本目录未来自行放入的画师图不自动获得公开授权。推送或发布这些新增图片前，需明确确认素材可公开；私人参考、草稿和用户皮肤不应复制进发行包。
