# Q弹汤圆 · Phase 1

本地离线桌宠原型。当前包含透明置顶窗口、四张 PNG 表情接入、无图兜底、呼吸与果冻形变、拖拽抛投、工作区碰撞和系统托盘。Python 3.10+，PySide6 6.8.3。

## 立即运行

本次已在 D:\Codex\Q弹汤圆\.venv 安装好依赖。PowerShell 执行：

    Set-Location -LiteralPath 'D:\Codex\Q弹汤圆'
    .\.venv\Scripts\python.exe main.py

使用已激活的项目虚拟环境时，也可以直接执行 python main.py。

在其他电脑首次安装：

    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe main.py

项目资源相对于 main.py 定位；从其他工作目录启动也能找到皮肤和样式。程序默认出现在主屏幕工作区右下角；托盘图标可能位于 Windows 的折叠图标区。

## 四张表情 PNG

将自己的透明背景 PNG 放到 assets/skins/default/：

| 文件 | 触发条件 |
| --- | --- |
| idle.png | 默认待机；它同时承担基础外观 |
| happy.png | 点击后显示 0.8 秒 |
| dizzy.png | 左键移动超过 5 个逻辑像素后，拖拽期间显示 |
| flat.png | 托盘或右键菜单的“切换测试饿扁状态”开启后显示 |

按本阶段列出的四个文件名接入，不需要额外的第五张基础图。当前没有附带外部美术图片，直接运行会使用柔和渐变的无五官圆形兜底。切换表情的真实 PNG 加载已通过测试图片验证；测试图片保存在 tests/artifacts/，没有混入正式皮肤目录。

- 建议四张图使用相同构图，单张 256×256 或 512×512，最长边不超过 4096。
- 加载时裁去透明边，并映射到统一的 128×116 逻辑身体外框。表情差分应尽量保持相同身体比例，避免切换时外观尺寸突变。
- flat.png 也先归一化到身体外框，再由程序统一压到约 40% 高度，避免“图片已经扁了、程序再压一次”。
- 贴图始终使用底部中心锚点。呼吸、点击、拖拽、落地变形均保留。
- 某张表情缺失时优先使用 idle.png；idle.png 也缺失时使用圆形兜底。损坏、全透明、超限图片会被跳过并在终端提示。
- 放入或更换图片后，在托盘或桌宠右键菜单选择“重新加载表情 PNG”，立即读取。

## 依次验收

1. 启动：确认无边框、透明背景、全局置顶；任务栏没有主窗口按钮；右下角托盘可找到图标。
2. 呼吸：静置观察高度约 ±3.3% 的缓慢变化，宽度反向补偿，脚底保持在工作区底边。
3. 单击：左键点一下，身体瞬间压扁变宽、轻跳并回弹。已有 happy.png 时显示 0.8 秒后恢复 idle.png。
4. 阈值：按住左键轻微移动不足 5 个逻辑像素后松手，仍算一次点击；超过阈值才开始拖拽。
5. 拖拽：把汤圆拖到屏幕上半部，左右晃动，倾角应平滑变化且不超过 ±18°；已有 dizzy.png 时切换为该图。
6. 抛投：横向甩出后松手，观察保留部分惯性、重力下落、边缘反弹。拖高后释放应比低处释放产生更明显的落地压缩。
7. 停住再放手：拖动后停住约 0.2 秒再释放，应垂直落下，不沿用很早以前的甩动速度。
8. 饿扁：通过托盘或右键菜单切换，身体应约为正常高度的 40%，脚底仍贴底；关闭后恢复。这只是 Phase 1 测试开关。
9. 多屏：如有多屏，按住拖到另一屏后松手，应使用该屏工作区；修改缩放或任务栏占用区域后，落点应随工作区更新。
10. 复位：选择“重置回主屏幕右下角”；不管此前是否拖动，都应返回主屏幕并清除运动速度。
11. 热加载：放入四张 PNG 后重载，分别检查待机、点击、拖拽、饿扁的表情；移走图片的测试请由用户自行操作，程序自身不删除图片。
12. 退出：选择“退出程序”，确认托盘与桌宠同时消失，启动终端恢复提示符。

Phase 1 的双击表现为连续戳一戳；后续主面板完成后再接入双击打开，空翻保留独立菜单入口。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| main.py | QApplication、统一控制器、托盘、共享右键菜单、异常退出和启动诊断 |
| pet_engine.py | 状态优先级、底部锚点形变、阻尼弹簧、重力/碰撞、PNG 缓存和备用绘制 |
| pet_window.py | 透明 Tool 窗口、60 Hz 调度、Qt 逻辑坐标映射、多屏选择、点击/拖拽识别及信号 |
| requirements.txt | 固定 PySide6 版本 |
| styles/theme.qss | 柔和色系菜单样式 |
| tests/test_phase1.py | 30 项物理、渲染、鼠标交互回归测试 |
| tests/verify_native.py | Windows 原生窗口属性、托盘动作、脚底坐标和退出验证 |

模型、存档管理器、养成面板属于后续阶段，本阶段没有添加空实现或无效导入。config/、data/、assets/icons/、assets/accessories/ 已预留目录。

## 计时与边界说明

- 窗口以 PreciseTimer 和绝对帧期限调度，目标 60 Hz；运动按实际经过时间计算，避免帧率改变速度。实际显示流畅度仍受系统负载和桌面合成影响。
- 弹簧与碰撞使用不大于 1/240 秒的子步进；休眠等长时间停顿最多推进 0.1 秒物理，避免恢复瞬间飞出屏幕。
- 所有桌面位置均使用 Qt 逻辑像素，使用鼠标 globalPosition 和 QScreen.availableGeometry，不额外乘设备缩放比。
- 脚底通过 mapFromGlobal 映射到绘制坐标，修正 150% 等非整数缩放下原生窗口原点的取整偏移。
- 地面使用工作区下边界，而不是硬编码任务栏高度；自动隐藏任务栏时遵循系统当时报告的工作区。
- 拖拽过程中按鼠标所在显示器切换工作区；松手后在当前工作区运动。拖拽倾斜的包围盒同样受工作区约束。
- 鼠标捕获丢失时自动结束拖拽，避免宠物永久悬空。
- 底部中心是变形基准；倾斜碰撞使用保守的身体包围盒，旋转回正时同步对齐地面。

## 自动验证

    .\.venv\Scripts\python.exe -B tests\test_phase1.py
    .\.venv\Scripts\python.exe -B main.py --smoke-test
    .\.venv\Scripts\python.exe -B tests\verify_native.py

第一项测试可通过 QT_QPA_PLATFORM=offscreen 在无桌面环境运行。后两项使用真实桌面窗口，自动退出；原生验证脚本适用于 Windows。测试创建的图片和诊断结果保留在 tests/artifacts/ 下，不进行自动递归清理。

本次实际验证：Windows、Python 3.12.6、PySide6/Qt 6.8.3、单显示器、150% 缩放。30 项行为测试通过；原生冒烟两秒执行 120 次动画更新，退出码 0；Windows 置顶、Tool、透明分层属性及全部托盘动作验证通过，并确认退出后计时器与托盘已停止。

物理测试覆盖负坐标显示器、30/60/120/144 Hz、工作区改变、不同落高、丢失鼠标捕获和拖拽边缘。没有实测多块物理显示器同时连接，也没有验证其他操作系统；Python 3.10 的兼容性以所选依赖支持范围为基础，本次实际运行使用 3.12。
